# NextLat V2: Correctness Before Scaling

This is an ongoing local training experiment, not a default promotion or a
state-of-the-art claim. The prerequisite review is in
[the NextLat plan](../nextlat-dragon-plan-20260905.md).

## Objective Contract

The implementation follows the stop-gradient placement in
[NextLat v4](https://arxiv.org/html/2511.05963v4): target latents are detached,
decoder parameters are frozen on the auxiliary KL branch, and predictor/source
gradients remain connected. The experimental action embeddings are differentiable.
Regression and KL use independent valid-token/horizon means, and adding other
auxiliaries no longer divides the NextLat coefficient. Tokenizer-derived masks
exclude EOS/padding and transitions across BOS, including intermediate horizons.
NextLat is applied to pre-logit hidden states, not directly to rho.

Objective version 2 is recorded in launch manifests. Unversioned NextLat
checkpoints cannot silently exact-resume; a weights-only transfer is required.
Unsupported EMA-history, pipeline, distributed reduction and startup auto-batch
contracts fail closed. No production defaults have been changed.

## Completed Mechanical Checks

- Three core decoder tests: values and input VJPs, frozen head/conditioning
  parameters, and retained action-embedding gradients with tied embeddings.
- Seventeen focused language tests: masks, padding, detached targets, independent
  reductions, tokenizer ownership, manual recurrent-gradient parity, matched
  experiment profiles, training execution and resume protection.
- The existing exact temporal-credit test passes for uneven masked chunks.
- 128 schedule tests pass, including weighted carry validation and source exposure.
- Twelve experiment runner tests and four training-summary tests, including exact
  launch association, epoch counters, difficulty strata and model-token lengths.

These tests establish mechanics, not improved reasoning or continual learning.

## Experimental Controls

All runs use local release CUDA on GB10 unified memory, four shared-weight Dragon
layers, D=96, four heads, N=3072, approximately 1M parameters, linear attention
with ALiBi, and AdamW at 0.0003 with weight decay 0.01 and gradient clipping 1.
The predictor is allocated in every arm, including CE controls. All recorded
initial tensor hashes match. Source/input identities were unchanged during each
completed matrix; configs, sources and executable copies are in the evidence
bundles. Only training seed 13 has been evaluated so far.

The source is formal proof-action selection, semantic-step answers, live document
streaming with curriculum feedback disabled, and fixed training difficulty 0.
That fixed level is an experimental control, not a production difficulty cap.
The 64-item structural holdout panel includes 16 items each at difficulties 0-3;
thus its aggregate includes out-of-training-difficulty cases. It uses the existing
proof kernel, not an independently implemented mathematical checker. Free answers
are decoded without an oracle menu renderer or forced grammar.

## Capacity Experiment Prerequisite

The first D=256, N=16384 (~13M parameter) smoke failed before learning with
`Invalid vector size. Got 16 which should not be >8`. Peak whole-host usage was
12.15 GiB, not an OOM. Enabling Dragon's dedicated projection kernels did not
remove the failure. Failed and diagnostic attempts remain recorded in
`nextlat-capacity-smoke`, `nextlat-capacity-diagnostic`, and
`nextlat-capacity-kernel-smoke` under `target/experiments`.

The Burn 0.21 fusion planner uses the smallest input/output dtype to choose I/O
vector widths. A byte mask can therefore over-vectorize the floating-point
matmul. The documented local `burn-cubecl-fusion` backport restricts ordinary
matmul I/O vector selection to its numeric operand storage widths. It preserves
other fusion routines and the separate quantized selection path. The CUDA
regression compares fused/unfused values, masks and input/weight gradients at
three projection shapes and passes (1 test, 1.69 seconds execution). This is
mechanical validation, not a learning improvement. The release training smoke
and matched capacity/objective matrix are required before drawing that conclusion.

The full CUDA-filtered kernel suite also passed: 20 tests, zero failures or
ignored tests, 16.41 seconds. This includes dense attention and projection
gradients, streaming recurrent input/terminal-rho VJPs, and the Mamba3 custom
backward comparison. These tests used the optimized debug-profile test binary;
training performance comparisons use the separate release binary.

The patched release smokes both completed 128 steps, validation, 64 free-answer
probes and checkpointing with unchanged source provenance:

## Memory Timescale Investigation

The guarded 128-step batch smokes passed at batch 16 (67.43 seconds, 13.83 GiB
peak host) and batch 32 (116.59 seconds, 21.93 GiB). These include validation and
checkpoint overhead; neither short run learned verified completions. The planned
4,096-step batch-32 supervision matrix was deliberately terminated with SIGTERM
after 83.51 seconds, before its first validation, on discovery of a more direct
architecture issue. Its `process_failed` / exit -15 record is an operator stop,
not an OOM or spontaneous model failure. The second arm did not start.

`default_alibi_slopes(4)` currently returns approximately
`[1, 0.8408964, 0.7071068, 0.5946036]`. The recurrent kernel uses
`rho_next = exp(-slope) * (rho + write)`. Thus the direct-write half-lives are
only 0.69 to 1.17 tokens. The slowest head retains about 2.97e-17 of a write
after 64 tokens. This is NOT a proof that a multilayer nonlinear model cannot
relay information, but it makes direct long-range memory and credit severely
attenuated. Longer TBPTT credit does not remove this decay.

The [official ALiBi implementation](https://github.com/ofirpress/attention_with_linear_biases/blob/master/fairseq/models/transformer.py)
uses four-head slopes `[0.25, 0.0625, 0.015625, 0.00390625]`, while the
[public BDH baseline](https://github.com/pathwaycom/bdh/blob/main/bdh.py)
uses RoPE without this exponential forgetting. The immediate controlled screen
compares existing ALiBi and RoPE conditional training without changing checkpoint
interpretation or production defaults. A configurable, validated ALiBi timescale
contract and numerical long-lag tests are required before promoting a correction.

This is a documented precision contract, not a gradient-kernel or learning gain.
